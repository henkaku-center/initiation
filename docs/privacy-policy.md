# プライバシーポリシー

- 初版候補作成日: 2026-08-18
- 適用開始: henkaku Initiation の本番公開日

henkaku Community（以下「運営」）は、henkaku Initiation（以下「本サービス」）で扱う情報を、サービスの提供と安全な運営に必要な範囲に限って利用します。

この方針は、現在のフェーズ1 MVP-1を対象とします。未実装の質問箱、外部公開ビュー、AIによる回答案には適用せず、それらを導入する前に取得項目、公開範囲、保存期間を改めて決め、この方針を更新します。

## 運営者と問い合わせ先

- 運営者: henkaku Community
- 問い合わせ先: henkaku Community のDiscordサーバー内の問い合わせチケット

運営者の住所および代表者に相当する連絡責任者の情報は、問い合わせチケットから求められた場合に遅滞なく回答します。

問い合わせには、対象のウォレットアドレスと希望する対応を記載してください。本人確認が必要な場合は、ウォレット署名をお願いします。シードフレーズ、秘密鍵、サービスのAPIキーを尋ねることはありません。これらをチケットへ投稿しないでください。

## 取得する情報と利用目的

| 区分 | 取得・保存する情報 | 利用目的 |
| --- | --- | --- |
| ウォレット接続と認証 | ウォレットアドレス、チェーンID、初回認証日時、SIWEのメッセージ・署名・nonce | ウォレットの所有確認、サインイン、セッション管理 |
| メンバー情報 | ウォレットアドレス、任意の表示名（本人が設定できる機能を導入した場合） | メンバーの識別、申請と進捗の紐付け |
| Initiation | ステップID、回答、完了日時 | 進捗の保存・再表示、完走判定 |
| チェックイン | チェックイン日と記録日時 | 活動記録の保存・再表示 |
| 申請と運営記録 | 申請状態、審査・処理日時、判断理由、トランザクションID、操作した管理者のウォレットアドレス | 申請の審査、Allowlist追加とトークン配布、結果の表示、誤操作や重複処理の防止、監査 |
| 不正利用対策 | 対象ウォレットアドレス、操作種別、回数、集計期間 | 過剰な操作の制限、障害・不正利用の調査 |
| アクセス情報 | アクセス日時、リクエスト先、応答状態、IPアドレス、ブラウザ情報等をホスティング事業者が処理する場合があります | 配信、セキュリティ確保、障害調査 |
| 問い合わせ | Discordのアカウント情報、問い合わせ内容、対応履歴 | 問い合わせへの回答、開示・訂正・削除等の手続 |

SIWEのメッセージ、署名、nonceは認証のために一時的に処理しますが、運営のデータベースには保存しません。認証前はnonceを、認証後はウォレットアドレスとチェーンIDを暗号化した必須Cookieに保存します。

本サービスは、シードフレーズ、秘密鍵、メールアドレス、電話番号、住所の入力を求めません。Initiationの回答にも、公開したくない個人情報や秘密情報を記載しないでください。

現在のMVP-1には表示名の入力機能がなく、表示名を新たに取得しません。入力機能を追加する場合は、取得前に本人へ用途と公開範囲を示します。

## 公開範囲と閲覧できる人

- ウォレットアドレスはブロックチェーン上の公開情報ですが、運営は、ウォレットアドレスと表示名、Initiationの回答、進捗、チェックイン履歴との対応を一般公開しません。
- 本人は、自分の進捗、チェックイン履歴、申請状態と本人向けの判断理由を閲覧できます。
- `ADMIN_ADDRESSES` に登録された管理者は、申請者のウォレットアドレス、表示名、申請状態、判断理由、トランザクションID、操作履歴を閲覧できます。
- データベースやホスティング環境を管理する担当者は、保守、問い合わせ対応、セキュリティ対応に必要な場合に限り、保存された情報へアクセスします。
- Initiationの回答、チェックイン履歴、申請の内部記録を、広告、販売、メンバーの評価ランキングには利用しません。

Allowlist追加やトークン配布を行うと、対象ウォレットアドレス、トランザクションID、実行日時などがPolygon上で公開されます。ブロックチェーン上の記録は、運営が後から削除または訂正できません。

現在、匿名投稿、質問箱、外部公開ビューはありません。表示名を保存する機能を導入する場合も、本人の選択なしにウォレットアドレスとの対応を一般公開しません。

## Cookie

本サービスは、サインイン状態を保つために `initiation_session` Cookieを使用します。このCookieは必須で、広告やアクセス解析には利用しません。

- 有効期間: サインインから14日。閲覧だけでは延長しません
- 保存内容: 認証前はnonce、認証後はウォレットアドレスとチェーンIDを暗号化したもの
- 属性: `HttpOnly`、`SameSite=Lax`、本番環境では `Secure`
- 削除: サインアウト時または有効期間終了時

Cookieを無効にすると、サインインが必要な機能は利用できません。

## 保存期間

必要以上に長く保存しないため、次の期間を基準に削除または個人との紐付けを解除します。少なくとも年1回、保存を続ける必要があるかを見直します。

| 情報 | 保存期間 |
| --- | --- |
| 認証Cookie | サインインから14日。サインアウト時は直ちに削除 |
| メンバー情報、Initiationの回答・進捗、チェックイン | 最後に記録された活動から1年 |
| 申請、判断理由、トランザクションID、監査記録 | 申請の審査・Allowlist追加・配布に関する最後の処理から3年 |
| レート制限記録 | 対象となる集計期間の終了から30日 |
| 問い合わせ記録 | 対応完了から1年 |
| ホスティングの実行ログ | 契約プランに応じて1時間から30日 |

申請記録に必要なメンバー情報は、申請記録と同じ期間保存します。係争、セキュリティ調査、法令上の義務など、保存を続ける合理的な理由がある場合は、必要な範囲と期間に限って保存することがあります。

削除した情報がバックアップに残る場合は、バックアップの保存期間が終わった時点で上書きまたは削除されます。バックアップから復元した場合は、すでに受け付けた削除を再適用します。

## 開示、訂正、削除等

本人は、問い合わせチケットから、運営が保有する本人の情報について次の対応を求めることができます。手数料はかかりません。

- 利用目的の確認
- 保存内容の開示
- 誤りの訂正、追加または削除
- 利用の停止または消去

運営は、ウォレット署名等で本人であることを確認したうえで、合理的な期間内に対応し、結果を回答します。法令、第三者の権利、セキュリティ、処理済みのオンチェーン操作の監査に必要な記録は、対応できない場合または一部を残す場合があります。その場合は理由を説明し、判断理由など不要な記述を削除する、個人との紐付けを解除するなど、影響を小さくする方法を検討します。

Polygon上の記録や、Discordが独自に保持する情報は、運営だけでは削除・訂正できません。それぞれのサービスで利用できる手続を案内します。

## 外部サービスと第三者提供

本サービスの運営に、次の外部サービスを使用します。SupabaseとVercelには、サービスの提供に必要な範囲で情報の取扱いを委託します。DiscordとGitHub Pagesを利用するときは、各サービスがそれぞれの方針に基づいて情報を処理します。

| サービス | 用途 | 方針 |
| --- | --- | --- |
| [Supabase](https://supabase.com/privacy) | PostgreSQLデータベース、バックアップ | Supabaseの契約とデータ処理条件に従います |
| [Vercel](https://vercel.com/legal/privacy-notice) | アプリの配信、実行ログ | Vercelの契約とプライバシー通知に従います |
| [Discord](https://discord.com/privacy) | 問い合わせチケット | Discordのプライバシーポリシーに従います |
| [GitHub Pages](https://docs.github.com/ja/site-policy/privacy-policies/github-general-privacy-statement) | 本方針を含む公開ドキュメントの配信 | GitHubのプライバシーステートメントに従います |

各事業者の設備や再委託先により、日本国外で情報が処理される場合があります。委託先、保存地域、安全管理措置について本人から問い合わせがあった場合は、契約上開示できる範囲で回答します。

運営は、次の場合を除き、保存した個人データを委託先以外の第三者に提供しません。

- 本人の同意がある場合
- 法令に基づく場合
- 人の生命、身体または財産の保護のために必要で、本人の同意を得ることが難しい場合
- その他、個人情報保護法その他の法令で認められる場合

本サービスは、保存した回答や行動記録をAIサービスへ送信しません。AI機能を導入する場合は、送信する情報、送信先、保存や学習への利用、オプトアウトの方法を導入前に決めます。

## 安全管理

運営は、保存情報へのアクセスを担当者と目的に応じて制限します。データベースへの接続情報はサーバー側だけで管理し、データベースのRow Level Security、暗号化されたセッションCookie、HTTPS、管理者ウォレットの許可リストを使用します。

漏えい、滅失、改ざん等が発生した場合は、影響範囲を確認し、アクセス停止、認証情報の変更、復旧、関係者への連絡、必要な報告を行います。

## 方針の変更

取得する情報、公開範囲、利用目的に重要な変更がある場合は、変更案を公開し、意見を募集してから適用します。変更後の方針と適用日をこのページに掲載します。
