# 2026-08-18 MVP-1のプライバシー方針を公開レビューで定める（Issue #36）

- 課題: 本番公開前の条件としてプライバシー方針が必要だったが、現在の実装と将来案が同じ論点に混ざり、決定できないままになっていた。ウォレットアドレス自体は公開情報でも、Initiationの回答やチェックイン履歴と結びつけば、本人への影響は大きくなる。
- 決定: 現行のフェーズ1 MVP-1だけを対象に、[プライバシーポリシー](/privacy-policy)を開発者ドキュメントで公開する。Pull Requestは2026-09-01（JST）までDraftのまま意見を募り、意見を反映・確認した後に初版としてマージする。

## 決めた範囲

### 1. 個人との紐付けを外部へ公開しない

ウォレットアドレスと表示名、Initiationの回答・進捗、チェックイン履歴との対応は一般公開しない。本人は自分の記録を閲覧できる。管理者画面は、申請処理に必要なウォレットアドレス、表示名、申請状態、判断理由、トランザクションID、操作履歴に限る。

データベースの保守担当者は技術的には全テーブルへ到達できるため、保守、問い合わせ、セキュリティ対応に必要な場合だけアクセスする。ウォレットアドレスがオンチェーンで公開されていることを理由に、アプリ内の行動履歴まで公開情報として扱わない。

### 2. 保存期間をデータの目的ごとに分ける

| 情報 | 保存期間 | 理由 |
| --- | --- | --- |
| 認証Cookie | サインインから14日 | 実装済みの絶対期限と一致させる |
| メンバー、進捗、回答、チェックイン | 最終活動から1年 | 参加の再開とMVPの検証に必要な期間を取りつつ、放置データを残し続けない |
| 申請と監査記録 | 最後の申請処理から3年 | Allowlist追加とトークン配布の照会・誤処理調査に備える。無期限保存はしない |
| レート制限 | 集計期間終了から30日 | 通常の制限判定が終わった後、短期間の不正利用調査だけに使う |
| 問い合わせ | 対応完了から1年 | 対応内容の確認と再問い合わせに備える |

少なくとも年1回、期限を過ぎたデータと、目的がなくなったデータを確認して削除または個人との紐付けを解除する。Supabaseのバックアップに残る情報は、契約プランのバックアップ保存期間が終わるまで残り得る。復元時は、過去に受け付けた削除を再適用する。

個人情報保護委員会の[通則編3-4-1](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)と[FAQ Q5-2](https://www.ppc.go.jp/all_faq_index/faq1-q5-2/)は、一律の法定保存期間を置くのではなく、利用目的に必要な期間を設定し、必要がなくなった情報を遅滞なく消去する考え方を示している。上の期間はMVP-1の運用目的から置いた初版の基準で、実績を見て短縮・延長を提案できる。

### 3. 削除・訂正はDiscordチケットで受ける

本人は、Discordの問い合わせチケットから開示、訂正、削除、利用停止を求められる。必要に応じてウォレット署名で本人確認する。運営がシードフレーズや秘密鍵を尋ねることはない。

監査記録も自動的に無期限保存とはしない。係争、セキュリティ調査、処理済みのオンチェーン操作の確認に必要な最小限の記録は、理由と期間を限定して残すことがある。判断理由の自由記述など、監査に不要な情報は削除または紐付け解除を優先する。ブロックチェーン上の記録は運営側から削除できないことを回答時に説明する。

### 4. 外部サービスは委託先として明示する

本番構成で使用予定のSupabase、Vercelと、問い合わせに使うDiscord、公開文書を配信するGitHub Pagesを方針に列挙する。SupabaseとVercelは利用目的の達成に必要な範囲の委託先とし、広告やデータ販売には使わない。DiscordとGitHub Pagesは、利用者自身もアクセスする外部サービスとして各社の方針を案内する。個人情報保護委員会の[通則編3-6-3](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)が示す、委託先は委託された業務の範囲内で取り扱うという境界に合わせる。

実行ログとバックアップの期間は事業者の契約プランに左右される。[Vercel Runtime Logs](https://vercel.com/docs/logs/runtime)は1時間から30日、[Supabase Database Backups](https://supabase.com/docs/guides/platform/backups)は有料プランで7日から30日の範囲を案内している。契約プランを変更するときは、方針の記載と運用がずれないかを確認する。

### 5. 将来機能は初版へ先取りしない

質問箱、匿名投稿、外部公開ビュー、AI回答案は未実装なので、初版ではデータを取得・公開・AI送信しないと明記する。各機能を始める前に、必要な情報、閲覧者、保存期間、削除方法、AI事業者の学習利用を決め、方針の変更案を公開する。

## 採らなかった案

- 将来機能を含む完全な方針が決まるまで本番公開を待つ案。実装されていない機能の判断がMVP-1を止め続けるため採らない。
- 監査記録を無期限に保存する案。オンチェーンのトランザクションは別に残り、アプリ内の判断理由や個人との紐付けまで無期限に持つ必要性は確認できていない。
- ウォレットアドレスは公開情報なので、紐付く記録も公開できるとする案。回答や活動履歴の公開可否は、ウォレットアドレス単体の公開性とは別の判断である。
- アプリ内に専用ページを実装する案。Issue #36は方針を反映するコード変更を対象外としているため、初版はGitHub Pagesで公開し、アプリからの導線は別Issueで扱う。

## 公開前に確認すること

- henkaku Communityの運営者情報について、Discordチケットで住所と連絡責任者を遅滞なく回答する運用で十分か
- 本番Supabaseの保存地域とプラン、Vercelのプランが、方針に書いた国外処理とログ・バックアップ期間に収まるか
- 1年・3年・30日という保存期間が、実際の問い合わせと運営監査に対して長すぎないか、短すぎないか
- 期限到来データの削除、問い合わせ時の本人確認、バックアップ復元後の削除再適用を、誰が担当するか
- 法務の専門家による確認が必要か

マージ後、保存期間を実際の運用へ反映する作業は別Issueへ分ける。実装や運用手順が方針に追いつく前に本番でデータ収集を開始しない。
